# iLAMP — Intelligent Laboratory Animal Management Platform

ระบบบริหารจัดการข้อมูลสัตว์ทดลอง (หนู) สำหรับ **ศูนย์สัตว์ทดลอง คณะแพทยศาสตร์ มหาวิทยาลัยเชียงใหม่**

> **สถานะ: Interactive Prototype** — คลิกได้จริงทุกหน้า แต่ **ยังไม่เชื่อมฐานข้อมูล** ข้อมูลเป็น mock ในหน่วยความจำ รีเฟรชแล้วรีเซ็ต
> เป้าหมายของเฟสนี้คือทดสอบ **UX / workflow** กับผู้ใช้งานจริงในห้องแลปให้ตกผลึกก่อน แล้วจึงพัฒนาระบบจริงและต่อฐานข้อมูล

UI เป็นภาษาไทยทั้งหมด ยกเว้นคำศัพท์ในแบบฟอร์มราชการที่เป็นภาษาอังกฤษบนกระดาษต้นฉบับ — คงไว้ตามเดิมเพราะเป็นศัพท์เทคนิค

## วิธีเปิดใช้งาน

เปิด `index.html` ด้วยเบราว์เซอร์ได้เลย ไม่ต้องติดตั้งอะไร ไม่ต้องมีเซิร์ฟเวอร์ ไม่มี build step

บัญชีทดลอง — รหัสผ่าน `demo1234` ทุกบัญชี (ผู้ดูแลระบบ `admin@lab.test` / `admin1234`)
หรือกดปุ่ม **🧪 สาธิต** มุมขวาล่างเพื่อสลับบทบาทได้ทันทีโดยไม่ต้องล็อกอินใหม่

## ขั้นตอนการทำงานหลัก

ระบบเดินตามลำดับงานจริงของศูนย์ฯ ไม่ใช่แค่หน้าจอ CRUD

### 1. ขออนุมัติโครงการ — 3 ขั้น
```
PI ยื่นคำขอ → AEC (สำนักเลขาฯ จริยธรรม) ตรวจ → AV (หัวหน้าสัตวแพทย์) จัดสรรพื้นที่ → โครงการเริ่ม
```
- **PI** กรอกคำขอ: หัวโปรโตคอล (Protocol No., PI, Species, Strain, Lot No., ช่วงอายุ/น้ำหนัก, จำนวนแยกเพศ), กลุ่มการทดลอง 2 ชั้น, **แผนการใช้สัตว์ทดลอง** (เลือกวันที่จากปฏิทินไทย), ข้อกำหนดสิ้นสุดโครงการ และแนบเอกสารได้ไม่จำกัด
- **AEC / AV ตีกลับได้** พร้อมเหตุผลและ**เบอร์ติดต่อกลับ** ให้ PI สอบถามได้ทันที · เจ้าของคำขอแก้แล้วยื่นใหม่ได้
- **AV** กำหนดห้อง / แร็ค / ชั้น / รหัสกรงเอง — ไม่ใช่ตารางตายตัว แต่ละชั้นมีจำนวนกรงไม่เท่ากันได้ (สูงสุด 8 กรงต่อแถว) แล้วยืนยันกลุ่มทั้งสองชั้น
- **กรงถูกสร้างเป็นกรงว่าง** หนูยังไม่เข้า

### 2. รับหนูเข้าโครงการ (นักวิทยาศาสตร์)
ชั่งน้ำและอาหารที่ใส่เข้ากรงก่อน แล้วจึงชั่งหนูทีละตัวด้วยแป้นตัวเลขบนจอ · หนึ่งกรงหนึ่งเพศ สูงสุด 5 ตัว
**รหัสประจำตัวหนูออกตรงนี้** และติดตัวไปตลอด ไม่เปลี่ยนแม้ย้ายกรงหรือเปลี่ยนกลุ่ม

### 3. จัดกลุ่ม 2 ชั้น (PI/CoPI)
แยกกันคนละชั้น กำหนดเมื่อไหร่ก็ได้หลังหนูเข้ากรงแล้ว
- **ชั้นที่ 1 · ชนิดอาหาร** — กรงที่ไม่ได้กำหนดจะใช้อาหารทั่วไปโดยอัตโนมัติ
- **ชั้นที่ 2 · กลุ่มทดสอบ** — Control / Treatment ฯลฯ

หลังโครงการเริ่มแล้ว **กรงและหนูถูกล็อก** เพิ่ม/ลบไม่ได้ เหลือ 3 อย่างที่ทำได้: กำหนดชนิดอาหาร · กำหนดกลุ่มทดสอบ · ย้ายกรงไปชั้นอื่น
การ**เปลี่ยน**สิ่งที่เคยกำหนดไว้แล้วต้องพิมพ์ยืนยัน และระบบจะบอกก่อนว่ากระทบลำดับในกลุ่มของหนูตัวไหนบ้าง

### 4. ชั่งน้ำหนักรอบปกติ + งานสัตวแพทย์
ชั่งทีละกรงจนครบ แล้วกด **"เสร็จสิ้นรอบชั่งวันนี้"** เพื่อแจ้งผู้วิจัย (ถ้ายังไม่ครบจะถามยืนยันก่อน)

งานสัตวแพทย์เดินเป็นสายตามความเป็นจริง:
```
ใครก็ได้แจ้งผิดปกติ → VET เปิดเคส / สั่งการุณยฆาต / ตัดว่าปกติ → ปิดเคส
แจ้งหนูตาย → ซากเข้าช่องแช่แข็ง → Sci/VET จัดการซาก → ทำลาย หรือ ชันสูตร
```

## ฟีเจอร์

### ผังกรง (Dashboard)
จำลองตำแหน่งจริง — แร็ค → ชั้น → กรง · โครงการที่กินหลายแร็คจะแบ่งช่วงให้เห็นชัด
แต่ละกรงแสดงน้ำหนักหนูทุกตัว การเปลี่ยนแปลงรายวัน น้ำ/อาหารที่กิน ชนิดอาหารและกลุ่มทดสอบ

- **สีกรง** — เทา ปกติ · ส้ม มีหนูถูกแจ้งผิดปกติ รอสัตวแพทย์ · เหลือง กำลังรักษา · แดง สั่งการุณยฆาต
- **สีตัวเลขหนู** (ตามน้ำหนักที่เปลี่ยนต่อวัน) — เขียว ขึ้นปกติ · เหลือง ขึ้นน้อยกว่าเกณฑ์ · แดง ลด/ไม่เพิ่ม
- **เครื่องหมายบนตัวหนู** — `+` กำลังรักษา · `!` แจ้งผิดปกติ · `❄` ซากแช่แข็งรอจัดการ

### แบบฟอร์มราชการ — พิมพ์เป็น PDF ได้ทุกใบ
สร้างเอกสาร A4 ตามฟอร์มกระดาษของศูนย์ฯ โดยไม่ใช้ไลบรารีใด ๆ — เขียน HTML ลง iframe แล้วสั่งพิมพ์ ผู้ใช้เลือก "Save as PDF"

| ฟอร์ม | รหัส |
|---|---|
| รายงานอาการป่วย | LA Guide-AF 11.1-02 |
| บันทึกติดตามอาการ (Day 1–14) | LA Guide-AF 11.1-03 |
| รายงานการตายของสัตว์ทดลอง | LA Guide-AF 11.1-01 |
| บันทึกการผ่าชันสูตรซาก | LA Guide-AF 11.3-01 |

### ใบติดหน้ากรง
พิมพ์ตามใบจริงที่เสียบหน้ากรง **ขนาดนามบัตร 90 × 55 มม. · 10 ใบต่อหน้า A4**
ช่องที่ระบบยังไม่รู้จะพิมพ์เป็นเส้นเปล่าให้เขียนมือ เหมือนใบต้นฉบับ แล้วเติมเองเมื่อข้อมูลเกิดขึ้นจริง
เลือกพิมพ์ทั้งโครงการหรือเฉพาะบางกรงก็ได้ (สิทธิ์ PI / CoPI / AHS)

### อื่น ๆ
- **รายงานสรุประดับโครงการ** — รายงานการตาย · บันทึกติดตามอาการสัตว์ป่วย
- **กราฟ & Export CSV** — เทียบรายกลุ่ม/รายตัว กรองได้ทั้งสองชั้นพร้อมกัน · CSV ออกทั้ง Diet และ Group เพื่อ pivot ได้ทั้งสองแกน
- **การแจ้งเตือน** — กระดิ่งบนแถบบน กดแล้วเด้งไปหน้าที่เกี่ยวข้อง ครอบคลุมสายอนุมัติ สายปฏิบัติการ และสายสัตวแพทย์
- **เอกสารโครงการ** — แนบ PDF แยกหมวด (เดโมเก็บในหน่วยความจำ)
- **Audit Log** — บันทึกทุกกิจกรรม กรองตามประเภท เห็นเฉพาะโครงการที่ตนเข้าถึงได้
- **จัดการผู้ใช้** — ADMIN/AV เปิดบัญชีให้บุคคลภายนอก · ผู้ใช้เปลี่ยนรหัสผ่านเองได้

## ระบบสิทธิ์

สองชั้น **บวกกัน ไม่มีการหักออก** — สิทธิ์ที่ใช้ได้จริง = สิทธิ์ของตำแหน่ง ∪ สิทธิ์ของบทบาทในโครงการ

**1. ตำแหน่งระดับระบบ** — หนึ่งคนหนึ่งตำแหน่งเท่านั้น (13 ตำแหน่ง)

| | |
|---|---|
| ผู้ดูแลระบบ | ADMIN |
| สายปฏิบัติการ | AV (หัวหน้าสัตวแพทย์) · VET · SCI · ACT |
| สายกำกับดูแล | AEC · IACUC · QA · AUDIT · EX · OCH |
| สายสนับสนุน | GM · EXTERNAL (บุคคลภายนอก) |

**2. บทบาทในโครงการ** — ต่อโครงการ (6 บทบาท)
`PI · CoPI · AHS` คือทีมวิจัย · `Sci · VET · ACT ประจำโครงการ` ได้สิทธิ์เท่าตำแหน่งชื่อเดียวกัน **แต่เฉพาะในโครงการนั้น** จึงใช้แต่งตั้งบุคคลภายนอกให้ทำงานเฉพาะโครงการได้

เส้นแบ่งที่ตั้งใจให้ชัด:
- **PI ชั่งน้ำหนักเองไม่ได้** ถ้าไม่ได้รับแต่งตั้งเป็น Sci ของโครงการนั้นด้วย
- **AEC / EX** ดูรายละเอียดโครงการได้ แต่เข้าผังกรงไม่ได้ · **IACUC / AUDIT** เดินดูผังกรงได้ แต่กดเข้าดูรายกรงไม่ได้
- **หน้ากราฟ** เป็นผลงานวิจัย ไม่ใช่ข้อมูลสวัสดิภาพสัตว์ — สายกำกับดูแลจึงไม่เห็น
- **โครงการที่ปิดแล้ว** ดูได้อย่างเดียว บันทึกอะไรไม่ได้

ดูตารางสิทธิ์เต็ม (22 ความสามารถ) ได้ในระบบที่ **เมนูผู้ใช้ → ดูข้อมูลผู้ใช้ & สิทธิ์**

## โครงสร้างไฟล์

```
index.html        โครงหน้า + โหลด CSS/JS (มี ?v= กันแคช)
css/fonts.css     ฟอนต์ IBM Plex Sans Thai ฝังเป็น base64 — ใช้งานออฟไลน์ได้ ไม่พึ่ง Google Fonts
css/styles.css    สไตล์ทั้งหมด ใช้ CSS variables ไม่มี preprocessor
js/data.js        ข้อมูลจำลอง + ตารางสิทธิ์ + helper (DB, Data)
js/app.js         ตัวควบคุมทั้งแอป (App): routing, render, ทุก dialog, wizard ชั่งน้ำหนัก, ตัวสร้าง PDF
```

## เทคโนโลยี

Vanilla HTML / CSS / JavaScript ล้วน — **ไม่มี dependency ไม่มี framework ไม่มี build step**
กราฟเขียนเป็น SVG เอง · Export CSV ฝั่ง client · PDF ใช้ระบบพิมพ์ของเบราว์เซอร์ · การเคลื่อนไหวใช้ Web Animations API (เคารพ `prefers-reduced-motion`)

เลือกแนวนี้เพราะเป็นโปรโตไทป์ที่ต้องแก้ตามความเห็นผู้ใช้บ่อย ๆ และต้องเปิดได้ทุกที่โดยไม่ต้องติดตั้ง — เปิดไฟล์เดียวก็ใช้ได้

## ข้อมูลตัวอย่างในระบบ

| โครงการ | สถานะ |
|---|---|
| NAFLD Diet Study | กำลังดำเนินการ · 2 แร็ค 4 ชั้น 24 กรง 48 ตัว จัดกลุ่มครบแล้ว |
| Renal Function Study | เพิ่งอนุมัติ · 5 กรงว่าง รอรับหนูเข้า |
| Cardio Safety Study | รอ AEC ตรวจ |
| Hepatic Clearance Assay | ผ่าน AEC แล้ว รอ AV จัดสรรพื้นที่ |
| Metabolic Screen | ถูกตีกลับ รอแก้ไข |
| Behavioral Pilot | ปิดโครงการแล้ว |

หนูในข้อมูลตัวอย่างครอบคลุมทุกเคสที่ระบบรองรับ — แจ้งผิดปกติ · กำลังรักษา · รักษาหายแล้ว · สั่งการุณยฆาต · Stop (ตัดออกจากค่าเฉลี่ย) · ตายและส่งชันสูตร · ซากรอจัดการ
