# iLAMP — Intelligent Laboratory Animal Management Platform

ระบบบริหารจัดการข้อมูลสัตว์ทดลอง (หนู) สำหรับ **ศูนย์สัตว์ทดลอง คณะแพทยศาสตร์ มหาวิทยาลัยเชียงใหม่**

> **สถานะ: Interactive Prototype** — คลิกได้จริงทุกหน้า แต่ **ยังไม่เชื่อมฐานข้อมูล** ข้อมูลเป็น mock ในหน่วยความจำ รีเฟรชแล้วรีเซ็ต
> เป้าหมายของเฟสนี้คือทดสอบ **UX / workflow** กับผู้ใช้งานจริงในห้องแลปให้ตกผลึกก่อน แล้วจึงพัฒนาระบบจริงและต่อฐานข้อมูล

UI เป็นภาษาไทยทั้งหมด ยกเว้นคำศัพท์ในแบบฟอร์มราชการที่เป็นภาษาอังกฤษบนกระดาษต้นฉบับ — คงไว้ตามเดิมเพราะเป็นศัพท์เทคนิค

## ขั้นตอนการทำงานหลัก

ระบบเดินตามลำดับงานจริงของศูนย์ฯ ไม่ใช่แค่หน้าจอ CRUD

### 1. ขออนุมัติโครงการ — 3 ขั้น
```
PI ยื่นคำขอ → AEC (สำนักเลขาฯ จริยธรรม) ตรวจ → AV (หัวหน้าสัตวแพทย์) จัดสรรพื้นที่ → โครงการเริ่ม
```
- **PI** กรอกคำขอ: หัวโปรโตคอล (Protocol No., PI, Species, Strain, Lot No., ช่วงอายุ/น้ำหนัก, จำนวนแยกเพศ), กลุ่มการทดลอง 2 ชั้น, **แผนการใช้สัตว์ทดลอง** (เลือกวันที่จากปฏิทินไทย), ข้อกำหนดสิ้นสุดโครงการ และแนบเอกสารได้ไม่จำกัด
- **ร้องขอหัตถการเพิ่มเติม** — เลือกรายการที่หน่วยให้บริการ ระบุจำนวนหนูและจำนวนวัน ระบบคิด *จำนวนครั้ง = หนู × วัน* และค่าใช้จ่ายรายบรรทัดกับยอดรวมให้สด ๆ ขณะพิมพ์ · ขอทำเกินจำนวนสัตว์ที่ระบุไว้ไม่ได้ · ราคา ณ วันที่ยื่นถูกแช่แข็งลงในคำขอ ปรับราคากลางทีหลังยอดในคำขอเก่าไม่ขยับ
- **ร้องขอแต่งตั้งเจ้าหน้าที่** — คนที่ยังไม่มีบัญชี ผู้วิจัยกรอกชื่อ อีเมล และ**ตั้งรหัสผ่านเริ่มต้น**ไว้ในคำขอเลย สัตวแพทย์เปิดบัญชีตามนั้นตอนสร้างโครงการ (แก้ได้ถ้าจำเป็น) · เจ้าของบัญชีเปลี่ยนรหัสผ่านเองได้ภายหลังที่ **เมนูผู้ใช้ → เปลี่ยนรหัสผ่าน**
- **AEC / AV ตีกลับได้** พร้อมเหตุผลและ**เบอร์ติดต่อกลับ** ให้ PI สอบถามได้ทันที · เจ้าของคำขอแก้แล้วยื่นใหม่ได้
- **AV** กำหนดห้อง / แร็ค / ชั้น / รหัสกรงเอง — ไม่ใช่ตารางตายตัว แต่ละชั้นมีจำนวนกรงไม่เท่ากันได้ (สูงสุด 8 กรงต่อแถว) แล้วยืนยันกลุ่มทั้งสองชั้น
- **กรงถูกสร้างเป็นกรงว่าง** หนูยังไม่เข้า

### 2. กักกันโรค — ก่อนหนูเข้าโครงการ
```
สร้างกรงเสร็จ → รอรับหนูเข้ากักกันโรค → กำลังกักกันโรค → กำลังดำเนินการ
```
สัตว์ที่สั่งมายังไม่ใช่ "หนูในโครงการ" จนกว่าจะผ่านการกักโรค เดิมช่วงนี้ถูกยุบเป็น "ยังไม่มีหนู" ก้อนเดียว ซึ่งแยกไม่ออกว่ารอของมาส่ง หรือของมาถึงแล้วกำลังนับวันกักอยู่ — คนละงานคนละคนรับผิดชอบ

- **ตรวจสุขภาพรายตัวตอนนับรับสัตว์** (LA Guide-AF 9.1-03) — **ทำครั้งเดียว** ในวันที่นับรับสัตว์เข้าส่วนกักโรค ไม่ได้ตรวจซ้ำระหว่างกัก · กรอกกรงกักโรค น้ำหนัก ลักษณะทั่วไป และผลผ่าน/ไม่ผ่านรายตัว · **รอบนี้ยังไม่กำหนดรหัสหนู** รหัสประจำตัวออกตอนชั่งน้ำหนักแรกเข้ากรงโครงการ แถวจึงอ้างด้วยลำดับกับกรงกักโรค · บันทึกแล้วสถานะเปลี่ยนเป็น *กำลังกักกันโรค*
- **บันทึกการดูแลประจำวัน** (LA Guide-AF 9.1-01) — เป็นการ *ดูแลและสังเกตอาการ* (Animal Care) ไม่ใช่การตรวจสุขภาพซ้ำ · Animals / Feed / Water / Cage อย่างละ Normal-Abnormal พร้อม Job ที่ทำ · เจอ Abnormal ต้องระบุสิ่งที่พบ และระบบแจ้งสัตวแพทย์ทันที ไม่ใช่รอให้ครบกำหนดแล้วค่อยเห็น
- **ระยะกักมาตรฐาน 7 วัน** — เลือกวันเริ่มกัก ระบบเติมวันสิ้นสุดให้เอง แก้ได้ · ตั้งวันสิ้นสุดเองแล้วเปลี่ยนวันเริ่มทีหลัง ระบบจะไม่ไปทับค่าที่ตั้งไว้
- **สัตวแพทย์ปล่อยออก** — ประเมินสุขภาพ (ครั้งที่สองและครั้งสุดท้าย) แล้วปล่อยเข้าโครงการ สถานะจึงเป็น *กำลังดำเนินการ* · ปล่อยก่อนครบกำหนดกักต้องระบุเหตุผล
- **นำหนูเข้ากรงไม่ได้จนกว่าจะพ้นกักโรค** — ปิดที่ปุ่มและที่โหมด เพราะเป็นกฎของงาน ไม่ใช่การจัดหน้าจอ

### 3. รับหนูเข้าโครงการ (นักวิทยาศาสตร์)
ชั่งน้ำและอาหารที่ใส่เข้ากรงก่อน แล้วจึงชั่งหนูทีละตัวด้วยแป้นตัวเลขบนจอ · หนึ่งกรงหนึ่งเพศ สูงสุด 5 ตัว
**รหัสประจำตัวหนูออกตรงนี้** และติดตัวไปตลอด ไม่เปลี่ยนแม้ย้ายกรงหรือเปลี่ยนกลุ่ม

### 4. จัดกลุ่ม 2 ชั้น (PI/CoPI)
แยกกันคนละชั้น กำหนดเมื่อไหร่ก็ได้หลังหนูเข้ากรงแล้ว
- **ชั้นที่ 1 · ชนิดอาหาร** — กรงที่ไม่ได้กำหนดจะใช้อาหารทั่วไปโดยอัตโนมัติ
- **ชั้นที่ 2 · กลุ่มทดสอบ** — Control / Treatment ฯลฯ

หลังโครงการเริ่มแล้ว **กรงและหนูถูกล็อก** เพิ่ม/ลบไม่ได้ เหลือ 3 อย่างที่ทำได้: กำหนดชนิดอาหาร · กำหนดกลุ่มทดสอบ · ย้ายกรงไปชั้นอื่น
การ**เปลี่ยน**สิ่งที่เคยกำหนดไว้แล้วต้องพิมพ์ยืนยัน และระบบจะบอกก่อนว่ากระทบลำดับในกลุ่มของหนูตัวไหนบ้าง

### 5. ชั่งน้ำหนักรอบปกติ + งานสัตวแพทย์
ชั่งทีละกรงจนครบ แล้วกด **"เสร็จสิ้นรอบชั่งวันนี้"** เพื่อแจ้งผู้วิจัย (ถ้ายังไม่ครบจะถามยืนยันก่อน)

งานสัตวแพทย์เดินเป็นสายตามความเป็นจริง:
```
ใครก็ได้แจ้งผิดปกติ → VET เปิดเคส / สั่งการุณยฆาต / ตัดว่าปกติ → ปิดเคส
แจ้งหนูตาย → ซากเข้าช่องแช่แข็ง → Sci/VET จัดการซาก → ทำลาย หรือ ชันสูตร
```

### พัสดุ — วัสดุ และ ครุภัณฑ์
ทะเบียนของทั้งหน่วย แยกเป็นสองกล่องเพราะเงินเดินคนละแบบ และคำถามที่ถามก็คนละคำถาม

| | วัสดุสิ้นเปลือง (กล่องบน) | ครุภัณฑ์ (กล่องล่าง) |
|---|---|---|
| นับยังไง | จำนวนคงเหลือ + จุดสั่งซื้อ | รายชิ้น มีเลขครุภัณฑ์ |
| มูลค่าเป็นค่าใช้จ่ายเมื่อไหร่ | ตอน **เบิกออก** ไม่ใช่ตอนซื้อ | ทยอยตัด **ค่าเสื่อม** เส้นตรง (ราคาทุน ÷ อายุปี) |
| คำถามที่ต้องตอบ | ของจะหมดหรือยัง | เหลือมูลค่าเท่าไร ยังใช้งานได้ไหม |

ชนิดถูกล็อกตั้งแต่ตอนสร้าง เพราะมันคือตัวกำหนดวิธีคิดมูลค่า — เปลี่ยนทีหลังเท่ากับตีความยอดเก่าใหม่หมด
มีรับเข้า/เบิกออกพร้อมประวัติ · แจ้งซ่อม/ปิดงานซ่อมพร้อมค่าใช้จ่าย · แถบเตือนของต่ำกว่าจุดสั่งซื้อและงานซ่อมค้าง

### การเงิน — ปิดยอดรายเดือน
หน้านี้**ไม่เก็บตัวเลขของตัวเอง** นอกจากอัตราค่าฝากเลี้ยงกับค่าใช้จ่ายที่ไม่มีที่อื่นบันทึกไว้ ที่เหลืออ่านสดจากทะเบียนพัสดุและจากโครงการ ยอดจึงตรงกันเสมอ — เบิกวัสดุในหน้าพัสดุ ยอดเดือนนี้ขยับทันที

**รายรับ**
- **ค่าฝากเลี้ยง** = จำนวนสัตว์ × วันที่อยู่จริงในเดือนนั้น × อัตรา — นับรายตัว ไม่ใช่เอาจำนวนหนูวันนี้คูณจำนวนวัน หนูที่ตายกลางเดือนหยุดคิดตั้งแต่วันถัดไป
  · เริ่มนับตั้งแต่**วันที่รับเข้ากักโรค** ไม่ใช่วันเข้ากรง — ระหว่างกักหน่วยก็ให้อาหาร ให้น้ำ และดูแลทุกวันอยู่แล้ว โครงการที่ยังกักอยู่จึงถูกเรียกเก็บตามจำนวนตัวที่ตรวจรับ**ผ่าน**
- **หัตถการที่ฝากทำ** — ป้อนสาร ฉีดสาร เจาะเลือด ชั่งน้ำหนัก การุณยฆาต ผ่าซาก คิดเป็นครั้ง บันทึกรายโครงการ
  · แยกจาก**หัตถการที่ร้องขอ**ในคำขอสร้างโครงการ ซึ่งเป็น *ประมาณการ* ล่วงหน้า — หน้าการเงินเก็บเฉพาะ **สิ่งที่ทำจริง** เพื่อไม่ให้รายรับพองจากงานที่ยังไม่ได้ทำ
- อัตราตั้งเป็น**อัตรากลาง**ได้ และโครงการที่ตกลงราคาพิเศษไว้ตั้งอัตราของตัวเองทับได้

**รายจ่าย** — สามหมวดแรกไม่ต้องกรอกซ้ำ
1. วัสดุที่เบิกออกในเดือนนั้น
2. ค่าเสื่อมครุภัณฑ์ของเดือนนั้น (ค่าเสื่อมรายปี ÷ 12)
3. ค่าซ่อม — ลงยอดในเดือนที่**ปิดงานซ่อม** เพราะก่อนปิดงานยังไม่รู้ราคา
4. ค่าน้ำ ค่าไฟ ค่าจ้าง ฯลฯ — **กรอกเองในหน้านี้** เข้ายอดเดือนตามวันที่ที่กรอก

สรุปให้สองบรรทัดคู่กันเสมอ: **ผลต่างรวม** (คุ้มทุนไหม) กับ **ผลต่างเงินสด** ที่ไม่รวมค่าเสื่อม (เงินสดพอไหม) — ค่าเสื่อมเป็นค่าใช้จ่ายที่ไม่ได้จ่ายออกจริงในเดือนนั้น

เดินดูย้อนหลังได้ทีละเดือน ปุ่มย้อนหยุดที่เดือนแรกที่มีรายการเกิดขึ้นจริง

### อัตราค่าบริการ (ผู้ดูแลระบบ)
**เมนูหลักของตัวเอง** ไม่ได้ซ่อนอยู่ในหน้าการเงิน เพราะไม่ใช่รายการทางการเงิน แต่เป็น *อัตรากลางชุดเดียวที่ทุกโครงการคิดจากมัน* — ของแบบนี้ซ่อนไว้ในหน้าที่บังเอิญเอาไปใช้ จะทำให้ดูเหมือนเป็นค่าที่ตั้งแยกรายเดือนหรือรายโครงการ ซึ่งตรงข้ามกับความจริง

เป็นต้นทางของราคาที่ทั้งคำขอของ PI และการเรียกเก็บรายเดือนหยิบไปใช้

- **แก้ราคาที่นี่ไม่กระทบยอดเก่า** — ทุกจุดที่บันทึกหัตถการจะคัดลอกราคา ณ ตอนนั้นไปเก็บกับรายการนั้น ราคาใหม่มีผลกับสิ่งที่บันทึกหลังจากนี้เท่านั้น
- **รหัส (`key`) ตั้งแล้วแก้ไม่ได้** เพราะเป็นตัวที่ประวัติทั้งหมดอ้างถึง — ชื่อกับราคาแก้ได้เสมอ
- **ลบได้เฉพาะรายการที่ยังไม่มีใครใช้** ตารางบอกจำนวนที่ถูกอ้างถึงแยกเป็น *ในคำขอ* กับ *เรียกเก็บแล้ว* · รายการที่ถูกใช้ไปแล้วใช้ **เลิกให้บริการ** แทน — หายจากช่องเลือกแต่ประวัติเก่ายังอ่านชื่อได้ และเปิดใช้ใหม่ได้ทุกเมื่อ

### อื่น ๆ
- **รายงานสรุประดับโครงการ** — รายงานการตาย · บันทึกติดตามอาการสัตว์ป่วย
- **กราฟ & Export CSV** — เทียบรายกลุ่ม/รายตัว กรองได้ทั้งสองชั้นพร้อมกัน · CSV ออกทั้ง Diet และ Group เพื่อ pivot ได้ทั้งสองแกน
- **การแจ้งเตือน** — กระดิ่งบนแถบบน กดแล้วเด้งไปหน้าที่เกี่ยวข้อง ครอบคลุมสายอนุมัติ สายปฏิบัติการ และสายสัตวแพทย์
- **เอกสารโครงการ** — แนบ PDF แยกหมวด (เดโมเก็บในหน่วยความจำ)
- **Audit Log** — บันทึกทุกกิจกรรม กรองตามประเภท เห็นเฉพาะโครงการที่ตนเข้าถึงได้
- **จัดการผู้ใช้** — ADMIN/AV เปิดบัญชีให้บุคคลภายนอกและตั้งรหัสผ่านใหม่ให้ได้เมื่อผู้ใช้ลืม · ผู้ใช้เปลี่ยนรหัสผ่านเองได้

## ระบบสิทธิ์

สองชั้น **บวกกัน ไม่มีการหักออก** — สิทธิ์ที่ใช้ได้จริง = สิทธิ์ของตำแหน่ง ∪ สิทธิ์ของบทบาทในโครงการ

**1. ตำแหน่งระดับระบบ** — หนึ่งคนหนึ่งตำแหน่งเท่านั้น (13 ตำแหน่ง)

| | |
|---|---|
| ผู้ดูแลระบบ | ADMIN |
| สายปฏิบัติการ | AV (หัวหน้าสัตวแพทย์) · VET · SCI · ACT |
| สายกำกับดูแล | AEC · IACUC · QA · AUDIT · EX · OCH |
| สายสนับสนุน | GM · EXTERNAL (บุคคลภายนอก) |

**2. บทบาทในโครงการ** — ต่อโครงการ (6 บทบาท)
`PI · CoPI · AHS` คือทีมวิจัย · `Sci · VET · ACT ประจำโครงการ` ได้สิทธิ์เท่าตำแหน่งชื่อเดียวกัน **แต่เฉพาะในโครงการนั้น** จึงใช้แต่งตั้งบุคคลภายนอกให้ทำงานเฉพาะโครงการได้

เส้นแบ่งที่ตั้งใจให้ชัด:
- **PI ชั่งน้ำหนักเองไม่ได้** ถ้าไม่ได้รับแต่งตั้งเป็น Sci ของโครงการนั้นด้วย
- **AEC / EX** ดูรายละเอียดโครงการได้ แต่เข้าผังกรงไม่ได้ · **IACUC / AUDIT** เดินดูผังกรงได้ แต่กดเข้าดูรายกรงไม่ได้
- **หน้ากราฟ** เป็นผลงานวิจัย ไม่ใช่ข้อมูลสวัสดิภาพสัตว์ — สายกำกับดูแลจึงไม่เห็น
- **โครงการที่ปิดแล้ว** ดูได้อย่างเดียว บันทึกอะไรไม่ได้

ตำแหน่งฝั่งสนับสนุนแยกจากงานสัตว์ชัดเจน — **GM** เห็นเฉพาะ พัสดุ + การเงิน ไม่เห็นโครงการเลยสักโครงการ · **EX** อ่านยอดการเงินได้แต่ลงรายการไม่ได้ · แท็บ **อัตราค่าบริการ** เห็นเฉพาะ ADMIN

ดูตารางสิทธิ์เต็ม (26 ความสามารถ) ได้ในระบบที่ **เมนูผู้ใช้ → ดูข้อมูลผู้ใช้ & สิทธิ์**

## โครงสร้างไฟล์

```
index.html        โครงหน้า + โหลด CSS/JS (มี ?v= กันแคช)
css/fonts.css     ฟอนต์ IBM Plex Sans Thai ฝังเป็น base64 — ใช้งานออฟไลน์ได้ ไม่พึ่ง Google Fonts
css/styles.css    สไตล์ทั้งหมด ใช้ CSS variables ไม่มี preprocessor
js/data.js        ข้อมูลจำลอง + ตารางสิทธิ์ + helper (DB, Data)
js/app.js         ตัวควบคุมทั้งแอป (App): routing, render, ทุก dialog, wizard ชั่งน้ำหนัก, ตัวสร้าง PDF
```

## เทคโนโลยี

Vanilla HTML / CSS / JavaScript ล้วน — **ไม่มี dependency ไม่มี framework ไม่มี build step**
กราฟเขียนเป็น SVG เอง · Export CSV ฝั่ง client · PDF ใช้ระบบพิมพ์ของเบราว์เซอร์ · การเคลื่อนไหวใช้ Web Animations API (เคารพ `prefers-reduced-motion`)

เลือกแนวนี้เพราะเป็นโปรโตไทป์ที่ต้องแก้ตามความเห็นผู้ใช้บ่อย ๆ และต้องเปิดได้ทุกที่โดยไม่ต้องติดตั้ง — เปิดไฟล์เดียวก็ใช้ได้

## ข้อมูลตัวอย่างในระบบ

| โครงการ | สถานะ |
|---|---|
| NAFLD Diet Study | กำลังดำเนินการ · 2 แร็ค 4 ชั้น 24 กรง 48 ตัว จัดกลุ่มครบแล้ว · มีเอกสารกักโรคย้อนหลังครบ |
| Bone Healing Study | 📦 รอรับหนูเข้ากักกันโรค · สร้างกรงแล้ว 5 กรง สัตว์ยังไม่มาส่ง ยังไม่มีเอกสารกักโรคสักใบ |
| Renal Function Study | 🦠 กำลังกักกันโรค · วันที่ 6 จาก 7 · ตรวจรับ 10 ตัว (ไม่ผ่าน 1) — พิมพ์ได้ทั้งสองใบทันที |
| Gut Microbiome Pilot | ⚖️ พ้นกักครบ 7 วันและสัตวแพทย์ปล่อยแล้ว · รอ Sci ชั่งน้ำหนักแรกเข้า |
| Cardio Safety Study | รอ AEC ตรวจ |
| Hepatic Clearance Assay | ผ่าน AEC แล้ว รอ AV จัดสรรพื้นที่ |
| Metabolic Screen | ถูกตีกลับ รอแก้ไข |
| Behavioral Pilot | ปิดโครงการแล้ว |

ทุกวันในข้อมูลตัวอย่างผูกกับ **วันที่สัตว์มาถึงหน่วย** ของโครงการนั้นวันเดียว (มาถึง → กัก 7 วัน → ปล่อย → ชั่งน้ำหนักแรกเข้า → สิ้นสุด) แผนการใช้สัตว์ · ใบฟอร์มกักโรค · Audit Log และสถานะจึงตรงกันเสมอ ไม่ว่าจะเปิดดูวันไหน

หนูในข้อมูลตัวอย่างครอบคลุมทุกเคสที่ระบบรองรับ — แจ้งผิดปกติ · กำลังรักษา · รักษาหายแล้ว · สั่งการุณยฆาต · Stop (ตัดออกจากค่าเฉลี่ย) · ตายและส่งชันสูตร · ซากรอจัดการ
